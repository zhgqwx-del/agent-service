# Redis ACL/AOF 冷启 CI 门禁规格

## 需求

### REQ-CIAOF-001 冻结完整受测源码

用受测提交的 Git 树确定精确路径、普通文件模式和 blob。入口核对 Git 索引路径以及磁盘模式与字节，冻结实际 SHA-256 和有序条目根。驱动前后重新验明同一清单全部条目，导出器验证冻结清单与源码见证。

### REQ-CIAOF-002 验证完整冷启和导出证据

保持 Redis 8.4.7 官方压缩包及构建、ACL 断言、同配置和同数据的两次原生冷启及结清。导出器要求上游报告的 26 个具名命令、52 份输出和 5 个容器结清，验证同 run/attempt/SHA 和精确文件集合。五份 AOF 证据合并后为 58 条清单记录。原有文件原字节保留。失败保留原错误及私有原件。

## 验收场景

### AC-CIAOF-001 精确源码集合

关联 [REQ-CIAOF-001](#req-ciaof-001-冻结完整受测源码)。

旧入口对 `166be40` 的 1217 条路径拒绝。候选接受完整的正式 Git 树，分别拒绝缺项、额外、同数量路径替换、字节漂移和执行模式漂移。驱动使用同一冻结清单核前后字节，根与条目数一致。

### AC-CIAOF-002 精确证据和两次原生冷启

关联 [REQ-CIAOF-002](#req-ciaof-002-验证完整冷启和导出证据)。

原生配置制品绑定受测提交、run 和 attempt。导出器拒绝缺失、额外、摘要错误、命令标签错误、身份混用和未结清。正常 Linux runner 必须实际完成 Redis 两次冷启，保持原始配置证据并发布五份 AOF 证据，继续既有镜像检查。
