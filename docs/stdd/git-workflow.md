# Git 工作方式

按 [AGENTS.md](../../AGENTS.md) 保留现有工作树和提交历史，默认在当前工作树接续。由 root 统一执行 Git 和网络操作。

## 开工

1. 用 `git status --short --branch --untracked-files=all` 查看分支、暂存区、未暂存和未跟踪文件。记录工作树、开发基线的引用与 SHA，以及需要保留的改动。
2. 任务涉及合入时，从任务要求、已有变更或 PR、项目约定确定实际目标，分别记录开发基线和合入目标。功能分支的 upstream 只能作为核对线索。目标明确后记录目标引用、可确认的 SHA 和同步策略。
3. 任务涉及同步、选定分支或独立工作树时，由 root 核对当轮范围，沿用已有授权并继承用户改动。使用本地引用或远端刷新失败时，记录实际来源和刷新状态。

## 收尾同步

1. 准备提交或 PR 时核对实际合入目标。任务需要刷新时，由 root 在当轮授权范围内刷新已确认的远端引用，再固定本轮目标 SHA，并记录同步前的分支和 HEAD。目标缺失、刷新失败或没有共同祖先时，记录最后核对的状态和交接入口。
2. 在同一目标 SHA 上核对候选和目标的祖先关系。候选已包含目标时记录这一事实。存在落后或分叉时，核对分支归属、共享历史、待同步的提交和工作区改动，由 root 按已授权的策略处理。保留原有暂存、未跟踪文件和已有 Git 操作的归属。
3. 若当轮授权包含临时保存本次改动，记录保存标识，并按标识恢复。恢复有冲突时保留保存记录，解决冲突后再做最终验收。
4. 出现同步冲突时，按双方意图、已确认规格和场景 ID 核对冲突文件及测试。记录仍需决定的事项及恢复入口，保留现场供续接。同步期间目标又前进时，按当轮范围重新确认目标和证据适用性。

## 提交前

1. 按[开发与 CI 指南](../operations/development-and-ci-guide.md#6-分层验证路径)执行适用的本地门禁，记录命令、退出状态、用例数量和结果。核对候选与实际受测 SHA 及源码字节的一致性，含未提交内容时按[验收记录模板](templates/verification.md)绑定受测字节。同步带来依赖变化时按项目命令同步依赖，受测内容变化后复跑受影响的检查。
2. 提交、推送和发布遵循当轮授权。同范围已有授权可直接沿用。

## 触发 CI 后

经授权提交并触发现有 CI 后，核对适用的完整 CI 证据与最终候选 SHA 对应，记录实际 run/attempt/SHA 及门禁结果。交接记录实际候选、证据和待补门禁。必跑门禁失败或缺证据时，保留待验收状态。
