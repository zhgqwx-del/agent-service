# 审查变更

1. 读 `AGENTS.md`，根据用户请求、PR 目标或仓库约定确定范围，由 root 解析并记录目标与指定候选的 SHA 或工作区基线。任务要求审查远端最新版本时，由 root 按当轮授权刷新已确认的引用，失败时说明实际采用的本地版本。审查已提交分支时，由 root 用 `python3 -B scripts/git_range.py --merge-base <目标SHA> <候选SHA>` 定位增量。审查工作区时，由 root 用 `git status --short --untracked-files=all` 枚举改动。结合 `git diff --cached`、`git diff` 和本轮范围内未跟踪文件的内容，覆盖三类改动并说明其与 HEAD 的关系。
2. 先扫改动范围和依赖，再读取目标 SHA 对应的评审规则（如有）、已确认的规格和实施方案。审查非当前候选时，由 root 从候选 SHA 读取文件，例如 `git show <候选SHA>:<路径>`。沿变更查调用方、已删除文件的残留引用、数据状态和副作用，核对边界、失败、兼容、并发或权限等与本次相关的风险。关注是否混入无关改动，以及删改测试断言和 CI 的实际理由。大变更优先核对受影响的关键入口，并交代未深入审查的范围。
3. 将 `REQ-*`、`AC-*`、测试和证据关联起来，核对受测提交或冻结快照是否对应当前候选，并核对讨论与 ADR 的状态、影响及可达性。缺少证据时列出待验证项，由 root 按本轮范围运行适用检查。
4. 按影响给出发现，附候选文件与行号、触发条件、受影响场景和可观察后果。区分已确认缺陷与仍需复核的问题。没有发现时，说明审查范围和证据限制。审查保持只读，保留当前工作树和分支。需要复跑非当前候选时，由 root 在隔离副本中执行并记录实际受测版本。
