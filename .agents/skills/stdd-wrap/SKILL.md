# 开发收尾与交接

1. 读 `AGENTS.md`、`docs/stdd/git-workflow.md` 和当前变更。按任务、PR 或变更记录核对当前候选、真实合入目标和对应远端。检查工作区和在途 Git 操作，记录 HEAD、目标引用与已核实的 SHA，保留现有工作树和历史。中途交接或离线时记录实际同步状态。
2. Git 和网络操作由 root 按本轮授权执行。涉及目标同步时，记录刷新状态和本轮目标 SHA，再按项目策略和候选关系处理，记录同步结果。发生冲突时按双方意图、已确认规格和场景 ID 逐项核对。仍有语义冲突时，保留现场、待决事项与恢复入口，暂停该候选的提交和推送。刷新受阻时记录所用快照和待办，可继续独立检查。
3. 同步实际交付的规范、契约和任务，按 `docs/stdd/decisions-and-discussions.md` 关联讨论与 ADR。适用验收完成后按项目约定归档，校验变更指向外部的相对链接和指回变更的索引、讨论及 ADR 链接。沿用已有的发布记录和工程文档位置，避免重复追加同一结论。
4. 如有同步，先恢复本轮临时保存的改动并解决恢复冲突，依赖有变化时按项目命令同步。核对最终候选差异与受测字节，提交前由 root 通过开发与 CI 指南的入口运行适用本地检查。经授权提交并触发现有 CI 后，按 `docs/stdd/git-workflow.md` 核对适用的最终 SHA 验收证据与 run/attempt/SHA。候选内容变化后核对证据并复跑受影响项。按 `docs/stdd/templates/verification.md` 记录目标 SHA、同步状态、实际受测版本、命令、用例数量及结果，仅追加报告时说明它对应的受测内容。必跑门禁失败或缺证时保留待验收状态。
5. 使用 PR 模板准备范围、方案确认、同步状态、受测证据、影响、待办和适用的恢复或前向修复条件。交接时保留绑定受测字节的候选标识、下一步和复跑入口。提交、推送、创建 PR 和发布依据本轮授权执行。交付时发现目标已前进，由 root 按当轮授权核对影响和适用的复验，交接未完成的同步与恢复入口。
