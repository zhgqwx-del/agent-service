# 生成验收记录

1. 读 `AGENTS.md`、`docs/engineering.md`、变更范围、确认后的规格和测试计划。结合实际差异和现有证据，按受影响的 AC 选择适用的定向、回归及手工检查，可复用项目已有的模块与场景映射，并按场景 ID 去重。核对实际测试入口、受测 HEAD 和相关工作区差异。
2. 由 root 按仓库约定运行适用检查，记录命令、退出状态、用例数量、环境、数据及绑定受测字节的提交 SHA 或冻结证据。CI 证据绑定 run/attempt/SHA，真实模型请求须有具名预算。分别标明断言失败、超时或环境阻塞、跳过及未执行。应执行但发现零条用例时，记录测试发现异常并标记待验证。保留原失败与已过结果，继续可独立执行的检查。
3. 手工验收按场景给出最小步骤、数据和预期。按实际观察或用户明确提供的实测结果记录执行人、环境、结果和证据来源，其余标为待验证。复用旧报告、截图或其他产物前，核对实际受测版本、环境与场景适用性。
4. 使用 `docs/stdd/templates/verification.md` 汇总自动与手工证据，回报通过、失败、阻塞、跳过和待验证的场景及复跑入口。候选同步或实现变化后，重新核对证据适用性，由 root 按仓库约定复跑受影响的检查并更新受测记录。是否可合入或交付按项目约定判定。需修复的问题交回相应实现任务。
