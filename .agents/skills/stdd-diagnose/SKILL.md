# 缺陷诊断与回归准备

1. 读 `AGENTS.md`，沿用项目反馈平台和访问方式，从本次授权的工单、日志、截图和本地代码收集证据。记录来源、发生时段与时区、应用版本、必要环境和复现数据，标明资料的取得、缺失及访问受阻情况。按时间范围和请求或会话标识定位相关日志，引用脱敏片段或原系统链接。由 root 核验环境和权限，并负责实际复现和对照检查。真实模型请求须有具名预算。
2. 对照反馈版本的规格，按时间线关联报错、输入、版本和调用链。本地代码与反馈版本有差异时记录差异。缩小复现数据，记录预期、实际结果、受影响版本和稳定的测试入口。需要时由 root 用正常样本核验影响边界。分别记录已复现事实、根因假设和待验证项。尚未复现时，交付已取得的证据、当前限制和复现入口。
3. 使用 `docs/stdd/templates/diagnosis.md` 记录诊断，可以合入现有工单。将能区分错误行为与正确行为的样例写成或关联一个 `AC-*`。
4. 交付最小复现或可继续复现的入口、已核实的影响范围和修复方向。需要实施时，把回归场景与实施方案交给 `stdd-start` 或按已有确认记录进入 `stdd-delivery`。
