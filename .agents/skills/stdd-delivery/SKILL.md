# 规范与测试驱动交付

1. 从仓库根目录读取 `AGENTS.md`、工程约定、变更及其规范、技术方案和测试。核对变更引用的讨论结论和生效 ADR。确认本次切片和实际工作区基线。代码和规范有冲突时列出差异，明确这次要修的对象。
2. 开发前核对规格、验收场景和实施方案已有确认记录。可以引用 `tasks.md`、工单、PR 或会话中已确认的方案。直接调用此技能且方案缺失时，先按 `stdd-start` 的口径给出修改位置、取舍和验证方法，等确认后再进入测试和实现。只要求审查、复现或复测时，按该任务范围执行。
3. 对行为变更优先从稳定的公开入口补测试。旧实现可运行时，由 root 执行定向检查，核实失败是否来自预期的行为差异。记录场景 ID、测试名和断言。单独记录环境或数据问题，恢复后由 root 复跑。
4. 实现确认过的最小切片，由 root 按 `docs/engineering.md` 先做类型检查与定向测试，再按候选和变更范围执行适用门禁。范围、接口、数据策略或验收口径发生实质变化时，先更新方案并重新确认受影响部分。原确认范围内的独立工作可以继续。
5. 按 `docs/stdd/templates/verification.md` 记录已确认的规格、绑定受测字节的版本证据、命令、实际结果和未覆盖项。后续分支同步或关键代码变化后，由 root 按项目约定复跑受影响检查。
